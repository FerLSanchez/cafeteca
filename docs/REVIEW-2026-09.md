## 3. Product review

### 3.1 What the app is today
A **personal bag cellar plus espresso log**: record bags (origin, roaster, process…), track their lifecycle (unopened → open → finished), track remaining stock by shots, keep one recipe per coffee and a brew log, and see stats (cost, preferences by origin/process, a Gantt of the month).

**Real value proposition:** "know which coffee to use today, how much is left, and which coffees I like best". Most of it works. What's missing is **closing the loop**: capture → decide → buy again.

## 6. Feature study — Bookoo scale via Web Bluetooth (PM-14)

**Source:** [BooKooCode/OpenSource](https://github.com/BooKooCode/OpenSource), MIT licence. It documents the BLE protocol of the **Mini scale** (updated Aug 2026), the **Ultra scale** (Sep 2026) and the **Espresso Monitor** (pressure).

### 6.1 Feasibility

| Question | Answer |
|---|---|
| Can a web page / PWA talk to the scale? | **Yes**, through the [Web Bluetooth API](https://developer.mozilla.org/docs/Web/API/Web_Bluetooth_API) (GATT client). It doesn't need the app to be installed as a PWA; a browser tab works too. |
| Browsers | ✅ Chrome/Edge on **Android**, Windows, macOS, ChromeOS. ❌ **iOS/iPadOS**: no browser supports it, because all of them use WebKit. The only workaround is a third-party browser with its own BLE bridge (e.g. Bluefy). ❌ Firefox. |
| Requirements | **HTTPS** (fine behind Authelia/TLS; `localhost` also works). A **user gesture** (a tap) to open the device chooser. No CSP change is needed. |
| Reconnection | The page loses the connection when it's closed. Reconnecting without the chooser (`navigator.bluetooth.getDevices()`) is not reliably available yet, so plan on **one tap per session** to pick the scale. |
| Exclusivity | A BLE scale accepts **one central at a time**. If the official Bookoo app is connected, the web app can't connect. |
| Backend impact | **None for the MVP.** `brews` already has `dose_g`, `yield_g` and `time_s`. Storing the flow curve needs a `migrate_v8`. |

### 6.2 Protocol summary (Mini and Ultra share the core)

- **Service** `0x0FFE` (full UUID `00000ffe-0000-1000-8000-00805f9b34fb`). **Characteristics:** `0xFF11` sends weight notifications, `0xFF12` receives commands.
- **Checksum:** the last byte is the XOR of all the previous bytes.
- **Commands (6 bytes)** `03 0A <cmd> <d1> <d2> <xor>`:

| Cmd | Action | Example frame |
|---|---|---|
| `01` | Tare | `03 0A 01 00 00 08` |
| `04` / `05` / `06` | Start / stop / reset the timer | `03 0A 04 00 00 0D` |
| `07` | **Tare + start timer** (recommended) | `03 0A 07 00 00 0E` |
| `08` | Flow smoothing on/off | `03 0A 08 01 00 00` |
| `0D` | *(Ultra, fw ≥ 4.0)* Set the powder (dose) weight, ×10 | — |
| `25` | *(Ultra, fw ≥ 4.0.1)* Keep awake (reset the auto-off countdown) | — |

- **Weight packet (20 bytes, type `0B`)**, 1-based:

| Bytes | Field |
|---|---|
| 3–5 | Timer in **ms** (uint24, big-endian) |
| 6 | Unit |
| 7 | Weight sign |
| 8–10 | **Weight × 100** (uint24) |
| 11 | Flow sign |
| 12–13 | **Flow × 100** (uint16, g/s) |
| 14 | Battery % |
| 15–16 | Standby time (min × 10) |
| 17 | Buzzer level |
| 18 | Flow smoothing on/off |
| 20 | Checksum |

- **Ultra only:**
  - Type `0F`: **powder weight**, i.e. the dose measured by the scale.
  - Type `0D`: **automatic-mode events** (ready / started / **stopped**). The stopped event carries the final time, weight and **average flow or ratio**, which is the ideal "shot finished" signal.
- **Espresso Monitor** (service `0x0FFF`): a **pressure** stream (bar × 100). This could come later.

### 6.3 Proposed user experience

1. From the coffee detail, tap **"⚖️ Shot with scale"** (next to "Register brew"). The first time, the browser opens its device chooser, filtered to service `0x0FFE`.
2. **Dose step:** put the portafilter or dosing cup on the scale and read the dose, then send `07` (tare + timer). On the Ultra, the dose comes directly from the `0F` packet.
3. **Live shot screen** (full screen, with a Wake Lock so the display stays on):
   - A large **timer**, the **weight**, and the **flow** in g/s.
   - A progress bar towards the **target yield** from the coffee's recipe, and the live **ratio**.
4. **End of shot:**
   - Automatic when flow is ~0 for about 3 s, or on the Ultra `0D`/`00` event.
   - Or manual: tap "Stop", which sends `05`.
5. The brew modal opens **pre-filled** with dose, yield and time, plus grind and temperature from the recipe. Add a rating and notes, then save. Stock is deducted by the brew's real `dose_g` (this aligns with ENG-04).

### 6.4 Technical design

| Piece | Detail |
|---|---|
| `static/js/scale.js` | `connectScale()`, `sendCmd(cmd, d1, d2)`, and a pure `parsePacket(DataView)` that validates the checksum and returns `{type, ms, weight, flow, battery}` or an event. It dispatches `scale:weight`, `scale:event` and `scale:disconnected` events. |
| Parser tests | Keep the parser free of side effects so it can be tested with `node --test`, using **real frames captured** from your scale as fixtures. |
| Simulator | A `?scale=sim` mode that emits a synthetic shot curve. It lets you develop and demo without hardware, and gives a Playwright test. |
| UI | A live-shot modal plus a small "⚖️ 87 %" connection chip in the nav. Hide the button when `navigator.bluetooth` is missing (iOS), and show a hint instead. |
| F2 data | `migrate_v8`: `brews.shot_curve TEXT` (JSON, downsampled to about 5 Hz: `[[t_ms, g, flow], …]`, ~2–3 KB per shot). Draw a sparkline in the brew detail. |

### 6.6 Risks and open questions

- ✅ **Model:** Themis **Mini**, latest firmware, used in **auto mode** (see §6.7).
- ✅ **Phone:** Pixel Pro (Android). Supported.
- ⚠️ **Sign bytes:** the docs don't say how the weight/flow "symbol" byte is encoded (likely ASCII `+`/`-`). The F0 spike settles it with real frames.
- ⚠️ The official Bookoo app must be **disconnected** while you use Cafeteca.
- ⚠️ The Ultra's firmware version changes command semantics (v3.x vs v4.x). Read it and adapt, or target v4+ only.

### 6.7 Decision: Themis Mini in auto mode (owner's setup)

**How the scale is used:** auto mode. The scale tares by itself when it detects the cup, starts the timer when flow begins, and stops it when flow ends.

**What this means for the design:**

| Topic | Implication |
|---|---|
| Published protocol | Bookoo's **Mini** doc only publishes the weight/timer/flow packet (`0B`). The auto-mode **events** (`0D`) and **powder weight** (`0F`) are only documented for the Ultra. The Mini may share that firmware and send them, but that is **not guaranteed**. |
| Integration style | Cafeteca only **listens** to the scale and **never sends commands** during a shot. The scale is in charge (auto-tare, timer), and on the Ultra, tare/timer commands are rejected while auto mode is running anyway. This is simpler and safer. |
| Shot start | The timer in the `0B` packet goes from 0 to increasing. If a `0D` event with state `01` arrives, use that instead. |
| Shot end | The timer **stops increasing for about 1.5 s**. If a `0D` event with state `00` arrives, use that instead. Then keep reading the weight for about 3 s so late drips count, and take the stable weight as the **yield**. |
| Time | The scale's own timer (ms → s). It matches what you see on the scale display. |
| Dose | The Mini doesn't publish it. Pre-fill it from the coffee's **recipe** `dose_g` (or `grams_per_shot`), and let you edit it before saving. |
| Flow curve | Record `[t_ms, weight, flow]` from start to stop, for F2. |

**Revised flow (touch-free during the shot):**
1. In the coffee detail, tap "⚖️ Shot with scale". This connects (one tap in the chooser) and shows "Waiting for the shot…".
2. Pull the shot as usual: the live view appears when the scale starts its timer.
3. When the scale stops its timer and the weight settles, the brew form opens pre-filled with dose (recipe), yield and time. Add a rating, then save.
4. Optional **continuous mode**: stay connected and create a brew draft for **every** shot while the page is open.

**Revised phases:**
- **F0:**
  - Connect and record a few real auto-mode shots, capturing the raw frames.
  - Confirm the sign-byte encoding and the packet rate.
  - **Check whether the Mini sends `0D`/`0F`.** If it does, use them. Otherwise rely on timer-based detection.
  - Optionally ask `develop@bookoocoffee.com` whether the Mini supports these packets.
- **F1:** passive auto-mode capture → pre-filled brew (above), plus a simulator that replays the F0 captures.
- **F3 (Ultra extras):** only the parts that F0 finds on the Mini.

**Dose step (confirmed):** before the shot, the owner weighs the ground coffee with the scale in **normal mode**. That value is the brew form's **"Café (g)"** field. The scale fills it too: a live reading that locks when the weight is stable, with an optional Tare button. That makes the dose real rather than taken from the recipe.
